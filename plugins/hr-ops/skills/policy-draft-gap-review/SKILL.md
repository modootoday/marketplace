# Policy draft gap review

A draft can read well and still miss a required element or contradict itself. Check it against
the list the user supplies, and report; do not fill the gaps with invented rules.

## Steps

1. Build the checklist first from the user's source rule or checklist, one required element per
   line, using the source's own wording (for example notice deadline, evidence requirement and
   its trigger, reporting channel, approval step). Keep that wording in the output table. Add generic elements (scope, roles,
   exceptions, review date) only as a labelled optional list the user may accept, never as
   findings against the draft.
2. For each element, search the draft and record one of: present (quote the clause), vague
   (quote it and say what is not specific, for example "ASAP" is not a deadline), or missing.
   Use missing, in those words, when no clause addresses the element at all, even if a nearby
   clause touches the topic: a channel the staff can use is missing when the draft names only
   someone to notify, and an approval step is missing when the draft only requires notice. Say
   in the note which neighbouring clause was found and why it does not satisfy the element.
3. Compare clauses with each other and with the source: numbers, durations, roles and
   conditions that disagree (for example a 3-day trigger in the source and 5 days in the draft).
   Quote both sides and name which one the source supports, without choosing a value for the
   owner.
4. Check who each duty sits on: a required step with no named role, or a reporting line that
   covers only one audience (for example management reports yearly but staff have no channel).
5. Leave facts that depend on the site or the organisation as explicit blanks for the owner
   (approval rules, names, thresholds not in the source), marked as owner to fill. Do not draft
   values for them.
6. Say what could not be verified: whether the checklist is complete, whether the draft follows
   current law or agreements, and anything outside the text supplied. State that legal, HR or
   the responsible owner reviews and approves the policy.

## Output

A table: element, status (present, vague, missing), quote or note. Then contradictions with both
quotes, the owner blanks, the optional generic elements, and a verification statement. Suggested
wording only if asked, and only as a labelled starting point.
