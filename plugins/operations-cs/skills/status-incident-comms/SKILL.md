# Incident communication

During an outage people want three things: is it me or you, what can I do, and
when will I hear more. An update that answers those, on time, beats a detailed
one late.

## Each update

- **Status word** the page uses (investigating, identified, monitoring,
  resolved), honestly applied.
- **Impact in user terms**: which feature, for whom (all users, one region, one
  payment method), since when, with the timezone.
- **What users can do**: a workaround, or "no action needed", or "do not retry
  payments until we update".
- **Next update time**: a specific time, and keep it even if there is no news.

## Do not

Guess a cause before it is confirmed, promise a fix time you do not control,
blame a vendor by name before they confirm, or use internal component names.

## Resolution note

When it ends: what was affected, the start and end time, that it is resolved,
anything users must do (retry, check a payment), and where a fuller report will
appear if there will be one.

## Language

Short sentences; Korean updates in polite haeyo-che. Same facts in every
channel (status page, email, community), posted from one source.
