# Newsletter issues

Readers decide in the inbox, from the sender, subject and preview text, and then
skim. An issue works when its single reason is clear in those three lines.

## Plan

- **The reason for this issue**: one sentence. If there is none, skip the week or
  send a shorter issue.
- **Lead item**: the most useful thing for the reader, not the most important
  thing for the company.
- **Recurring segments**: the same few sections in the same order every issue, so
  regular readers know where to look.

## Write

- **Subject**: the concrete value of the lead, under about 40 characters, no
  clickbait the body does not pay off.
- **Preview text**: completes the subject; never the default "view in browser".
- **Sections**: a heading, two to four sentences, one link or action each.
- One primary call to action per issue.
- Voice consistent with the community; Korean copy follows ux-writing-toss when
  installed.

## Before sending

Every link opens the right page with tracking parameters, images have alt text,
the issue renders on a phone and in dark mode, the unsubscribe link works, and a
test send has been read end to end.

## After

Note opens, clicks per section and replies; drop segments nobody clicks for
several issues.
