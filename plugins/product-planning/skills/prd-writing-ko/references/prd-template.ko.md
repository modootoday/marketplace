# PRD 예시: 메모 PDF 내보내기

## 1. 문제

노트 앱 사용자가 회의 메모를 거래처에 보낼 때 앱 밖으로 꺼낼 방법이 없다. 지금은 화면을 캡처해 여러
장의 이미지로 보낸다. 지난 분기 고객 문의 중 "PDF로 보내고 싶다"가 42건이었다.

## 2. 목표와 성공 지표

- 지표: 메모를 공유한 사용자 중 PDF 내보내기를 쓴 비율. 출시 후 4주 안에 15% 이상.
- 현재 값: 측정 전이다. 공유 이벤트 집계를 먼저 넣는다. (가정 아님, 미측정)

## 3. 사용자와 상황

- 거래처에 회의록을 보내는 개인 사업자
- 수업 노트를 출력하려는 학생

## 4. 범위와 하지 않는 것

- 하는 것: 메모 하나를 PDF 한 파일로 내보낸다.
- 하지 않는 것: 여러 메모 묶어 내보내기, PDF 편집, 서버 보관.

## 5. 요구사항

1. 메모 메뉴에 "PDF로 내보내기"가 있다.
   - 수용 기준: 메모를 연 상태에서 메뉴를 누르면 1초 안에 항목이 보인다.
2. 제목·소제목·이미지가 원본 순서대로 들어간다.
   - 수용 기준: 소제목 3개와 이미지 2장이 있는 메모를 내보내면 PDF에서 같은 순서로 보인다.
3. 50쪽 미만 메모는 5초 안에 끝난다.
   - 수용 기준: 49쪽 테스트 메모를 중간 사양 기기에서 내보낼 때 5초를 넘지 않는다.
4. 실패하면 다시 시도할 수 있다.
   - 수용 기준: 저장 공간이 부족하면 오류 문구와 "다시 시도" 버튼이 보이고, 메모는 바뀌지 않는다.

## 6. 화면 문구 (UI 어투: 해요체)

버튼은 누르면 일어나는 일을 동사로 쓴다. "PDF 내보내기"(명사) 대신 "PDF로 내보내기", "알림 신청"
대신 "알림 받기". 알림 문구는 소식을 전하고, "곧 품절돼요" 같은 재촉은 쓰지 않는다.

- 메뉴: PDF로 내보내기
- 진행: PDF를 만들고 있어요
- 완료: PDF를 저장했어요
- 오류: 저장 공간이 부족해요. 공간을 비운 뒤 다시 시도해 주세요

## 7. 열린 질문

- 이미지 해상도 기준은? (디자인 리드, 10월 10일까지)

## 8. 가정

- 중간 사양 기기는 출시 2년 이내 안드로이드 기기로 본다. (가정)
