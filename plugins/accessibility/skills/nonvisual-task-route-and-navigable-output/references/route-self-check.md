# Route self-check

Run this on the finished reply before sending it. Fix every hit.

## Words to search for and remove

- Layout or position: left, right (except the Left Arrow and Right Arrow keys), top, bottom,
  above, below, under, over, next to, nearby, beside, side, corner, around, upper, lower.
- Visual objects: icon, avatar, picture, image, logo, color names, QR code seen on screen
  (say "the setup key shown as text", and tell the user to look for a text option).
- Mouse: click, hover, scroll, drag, tap, point.
- Certainty about an unseen app: "will show", "will appear", "you will see", "the page has".
  Write "usually", "may" or "often" and name the check the user can do by ear.

## Worked step

## Step 3: Open the security part of the settings

Summary: This step moves you to the part of settings that deals with sign-in.

1. Press H until NVDA reads a heading with the word security or sign-in in it. If there is no
   such heading, press NVDA+F7 and choose the headings list.
2. If a button with that name is announced instead, press Enter on it.

Completion signal: NVDA reads a heading or page title that contains security or sign-in.

If it does not match: press NVDA+Tab and read back what NVDA says for the control in focus.

## Shape of the whole reply

1. "Step 1: What I assume and what to have ready": what is assumed and unverified, one line each.
2. Steps 2 to N-1, the actions: one heading level, one number, one summary sentence, actions,
   completion signal.
3. "Step N: What to read back if a step does not match": the step number, the heading text, the
   name and role announced for the focused control.
Every heading carries its number; none is unnumbered.
